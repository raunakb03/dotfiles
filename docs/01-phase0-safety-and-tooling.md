# Phase 0: Safety & tooling

Before touching any config, make sure you can always get back to a working
desktop and that your editor helps you instead of guessing.

Nothing in this phase changes how your desktop looks.

---

## Step 0.1: Know your escape hatch

**Why:** You'll be editing the compositor you're running inside. If a config
error ever leaves you with a broken session, you need a way out that doesn't
depend on Hyprland.

**Learn:**
- `Ctrl + Alt + F3` switches to a text console (TTY). Log in there.
- From the TTY you can edit files (`nano ~/.config/hypr/hyprland.lua`), restore
  backups, or rename a broken file away.
- `Ctrl + Alt + F1` (or `F2`) goes back to your graphical session.
- `hyprctl reload` re-reads the config without logging out.
- `hyprctl configerrors` prints any config errors. Hyprland also shows them in
  a red bar at the top of the screen.

**Check:** press `Ctrl + Alt + F3`, see a login prompt, then press
`Ctrl + Alt + F1`/`F2` to come back. Now you know the way out works.

## Step 0.2: Back up the current Hyprland config

**Why:** Your working `hyprland.conf` is the fallback if the Lua migration goes
wrong.

**Run:**
```bash
mkdir -p ~/hypr-backup-$(date +%F)
cp -a ~/.config/hypr/. ~/hypr-backup-$(date +%F)/
ls ~/hypr-backup-$(date +%F)
```
- `cp -a` = archive mode: copies recursively and keeps timestamps and
  permissions.
- The `/.` at the end of the source copies the *contents* of `hypr/`, dotfiles
  included.

**Check:** you see `hyprland.conf`, `hyprlock.conf`, `hyprlock.png` and
`hyprpaper.conf` in the backup folder.

## Step 0.3: Put `~/.config/hypr` under git

**Why:** From Phase 1 on, every change is a small commit. `git diff` shows
exactly what you changed. `git log` becomes a history of *why*.

**Write:** `~/.config/hypr/.gitignore`
```gitignore
# Large binary images don't belong in a config repo
*.png
```

**Run:**
```bash
cd ~/.config/hypr
git init
git add .
git commit -m "Initial snapshot of hyprland.conf before Lua migration"
```

**Check:** `git log --oneline` shows one commit.

## Step 0.4: Put `my-first-shell` under git

**Why:** Same reason. Right now the repo only holds the guide (`docs/`),
`README.md` and `PROJECT_CONTEXT.md`. The shell code starts in step 0.7.

A `.gitignore` lists files git should never track. Here that's
`.qmlls.ini`, which Quickshell generates for your machine. (In Phase 9 we'll

**Write:** `~/.config/quickshell/my-first-shell/.gitignore`
```gitignore
# Generated by Quickshell for the QML language server (see step 0.6)
.qmlls.ini
```

**Run:**
```bash
cd ~/.config/quickshell/my-first-shell
git init
git add .
git status          # shows what will be committed
git commit -m "Initial commit: roadmap docs"
```

**Check:** `git status` says "nothing to commit, working tree clean".

## Step 0.5: Install the packages Phase 1 needs

**Why:** Caelestia's Hyprland config starts these helpers at login. We want
the same behaviour, so the programs have to exist. Read
`caelestia/hypr/hyprland/execs.lua` to see where each one is used.

| Package | What it's for |
| --- | --- |
| `wl-clipboard` | `wl-paste`/`wl-copy`: the Wayland clipboard CLI |
| `cliphist` | stores clipboard history (fed by `wl-paste --watch`) |
| `gnome-keyring` | stores secrets (Wi-Fi passwords, browser logins) |
| `polkit-gnome` | the password prompt when an app asks for root (e.g. mounting disks) |
| `trash-cli` | `trash-empty 30` clears trash older than 30 days at login |
| `hyprpicker` | colour picker bind (`Super + Shift + C`) |
| `lua-language-server` | autocomplete and errors for your Lua config |

**Run** (you run this; nothing is installed for you):
```bash
sudo pacman -S --needed wl-clipboard cliphist gnome-keyring polkit-gnome trash-cli hyprpicker lua-language-server
```
`--needed` skips packages that are already installed.

**Check:** `command -v cliphist wl-paste hyprpicker lua-language-server` prints
four paths, and `ls /usr/lib/polkit-gnome/` shows
`polkit-gnome-authentication-agent-1`.

> Not installed on purpose: `foot`, `thunar`, `fish` and `sweet-cursors`
> are Caelestia's app choices. You keep kitty, nautilus and zen-browser, set
> as your overrides in Phase 1.

## Step 0.6: Editor support

### Lua (Hyprland config)
**Why:** Hyprland ships type "stubs" at `/usr/share/hypr/stubs/hl.meta.lua`.
They describe every `hl.*` function, so the language server can autocomplete
it and flag typos *before* you reload. Caelestia does the same thing; see
`caelestia/.luarc.json`.

**Write:** `~/.config/hypr/.luarc.json`
```json
{
  "workspace": {
    "library": ["/usr/share/hypr/stubs"]
  },
  "diagnostics": {
    "globals": ["hl"]
  }
}
```
- `workspace.library`: extra files the language server reads for type info.
- `diagnostics.globals`: tells it `hl` is a real global (Hyprland injects it),
  so it doesn't warn "undefined global".

**Check:** open `~/.config/hypr` in your editor, type `hl.` in a `.lua` file,
and see suggestions like `hl.bind`, `hl.config`, `hl.on`.

### QML (Quickshell)
**Why:** The QML language server (`qmlls`, installed at
`/usr/lib/qt6/bin/qmlls` and `/usr/bin/qmlls6`) needs to know where
Quickshell's types live. Quickshell writes that information for you: create
an **empty** `.qmlls.ini` in the shell folder, and Quickshell fills it in the
next time the shell runs.

**Run:**
```bash
touch ~/.config/quickshell/my-first-shell/.qmlls.ini
```
Then start the shell once (step 0.7) and look inside the file. It now has
import paths in it.

**Check (after step 0.7, once `shell.qml` exists):** in your editor,
hovering `PanelWindow` in `shell.qml` shows its documentation.

> Editor setup: VS Code uses the "Qt Qml" extension; Neovim uses
> `lspconfig.qmlls` with `cmd = { "qmlls6" }`. Tell me which editor you use
> and I'll add exact settings here.

## Step 0.7: Running, reloading and reading logs in Quickshell

**Why:** You'll run the shell hundreds of times, so learn the loop now. This
is only about *running* things. Phase 2 explains what each QML line means,
so for now just type it and see it work.

**Write:** `~/.config/quickshell/my-first-shell/shell.qml`
```qml
import QtQuick
import Quickshell

ShellRoot {
    settings.watchFiles: true

    PanelWindow {
        anchors {
            top: true
            left: true
            right: true
        }
        implicitHeight: 30
        color: "#1e1e2e"

        Text {
            anchors.centerIn: parent
            color: "#cdd6f4"
            text: "Hello from my shell"
        }
    }
}
```
In one sentence each (details in Phase 2):
- **`ShellRoot`** is the root of every Quickshell config.
- **`PanelWindow`** is a window glued to screen edges. Anchoring it to top,
  left and right makes it a bar.
- **`Text`** draws the label in the middle of it.

**Run:**
```bash
quickshell -c my-first-shell
```

**Learn:**
- `-c my-first-shell` = "config name". Quickshell looks in
  `~/.config/quickshell/<name>/shell.qml`.
- **Hot reload:** `settings.watchFiles: true` makes Quickshell reload
  whenever you save a `.qml` file. Try it: change `color: "#1e1e2e"` to
  `"darkred"`, save, and watch the bar update without restarting.
- **Logs:** with the shell running, open another terminal and run
  `qs log -c my-first-shell -f`. `-f` means "follow", i.e. keep printing new
  lines. Every `console.log(...)` and QML error appears there.
- **Stop it:** `Ctrl + C` in the terminal that started it, or
  `qs kill -c my-first-shell`.
- **Break it on purpose:** delete a `}`, save, and read the error in the log.
  Then put it back. Recognising errors early is a big part of learning QML.

**Check:** add `Component.onCompleted: console.log("bar loaded")` inside the
`PanelWindow`, save, and see `bar loaded` in the log.

**Commit:**
`git add shell.qml && git commit -m "First shell.qml: hello bar"`
